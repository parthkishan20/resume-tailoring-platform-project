# Task 4.5 — Screenshots and README rewrite

**Role:** `docs`
**Closes:** D-61

## What this task did

Two halves, both against the real, running, shipped application, not the source read alone.

## Half 1: screenshots

Ran the real app locally:

```bash
cd frontend && npm install && npm run build
rm -rf ../backend/static && cp -r out ../backend/static
cd ../backend && uv sync
LLM_MOCK=true DB_PATH=... PDFS_DIR=... uv run uvicorn resumetailor.main:app --host 0.0.0.0 --port 8000
```

Drove it with a real Chrome browser (`claude-in-chrome` MCP tools), not a headless script and not a
description of what a screenshot would show.

**Environment gotcha, not a product bug.** The browser could not reach the server through
`http://localhost:8000` or `http://127.0.0.1:8000`, both returned a bare `{"detail":"Not Found"}`
that never reached the server's own access log (confirmed by tailing it: zero new lines for either
request). Binding uvicorn to `0.0.0.0` and navigating to the host machine's LAN IP
(`http://192.168.x.x:8000`) worked immediately, and every subsequent request logged correctly. This
matches a previously-recorded memory note (`e2e-testing-gotchas.md`) about a similar class of
`localhost`-resolution mismatch in this project's history, though the specific cause here (the browser
tool evidently not sharing this shell's loopback) is not identical to that note's Docker/IPv6 case.
Recorded here so a future task does not lose the same time rediscovering it.

**A real, previously undiscovered defect, found live.** Clicking "Start from the sample" on first run
422s immediately: `cv.phone: This is not a valid phone number`. The frontend's own onboarding sample
(`frontend/src/features/onboarding/sample.ts`, `SAMPLE_YAML`) carries the placeholder phone number
`"+1 555 000 0000"`, which `phonenumbers.is_valid_number` rejects (confirmed directly). This has
nothing to do with `LLM_MOCK` or the backend's own mock-fixture phone number (D-75) — it is the
frontend's static sample, reachable by every user, with no LLM involved. It became reachable the
moment task 4.4's release-gate triage made `PUT /api/master-resume` validate strictly (D-04's fix).
Registered as **D-89** (P1) in `PLAN.md` §2.1, with an addendum note after the wave-4 triage table
since it postdates that table. Not fixed here: the file is `frontend-features`'s, not `docs`'s, per
`AGENTS.md` Rule 2. Worked around for the rest of the screenshot pass by writing a small, valid
sample resume by hand and pasting it into the YAML editor via a synthesized `paste` `ClipboardEvent`
dispatched at `.cm-content` (the browser tool has no OS clipboard access in this sandbox;
`navigator.clipboard.writeText` itself threw `undefined`, so a real paste event with a manually built
`DataTransfer` was used instead — CodeMirror's own paste handler picked it up correctly, confirmed by
the resulting editor content).

## Half 2: the README

Rewritten in full against the real product, read alongside `PLAN.md`'s full Change log (§7) and
`docs/design/DESIGN-SYSTEM.md`:

- **Screenshots** section points at the eleven new files, in both themes where captured.
- **Features** rewritten to describe the actual three-zone workspace (nav rail, document region,
  inspector) and the four real inspector surfaces: Tailor, Evaluate, Library (with its real
  rename/edit/re-render/sort/pagination, not "view or re-download"), and Assistant with its real
  four-tool set (`edit_master_resume`, `generate_tailored_resume`, `evaluate_resume`,
  `update_generation_rules`).
- **Development Setup**: dropped the dead `PYTHONPATH=src` (D-65 made the backend a real installed
  package); added the `make dev-hot` (`docker compose --profile dev up`) hot-reload path as an
  alternative to running frontend and backend as separate processes; added `make backup` /
  `make restore` / `make migrate`.
- **Configuration**: rebuilt from `backend/src/resumetailor/core/config.py`'s actual `Settings`
  class. Split into two tables by judgment call: a short "what you'll actually set" table
  (`OPENAI_API_KEY`, `LLM_MODEL`, `LLM_MOCK`, `DB_PATH`, `PDFS_DIR`, `LOG_LEVEL`, `LOG_FORMAT`,
  `API_DOCS_ENABLED`) and an "Advanced tuning" table for the five `LLM_*` bounds plus
  `GRACEFUL_SHUTDOWN_TIMEOUT_S`, `REAPER_INTERVAL_S`, and `REAPER_DELETE_GRACE_S` — real, documented,
  but not what a first-time reader needs to see first. `SECURITY_*` (rate limiting, body caps) and
  `RENDER_*` (RenderCV overlay paths, render timeout/concurrency) live in `core/security.py` and
  `rendering/config.py` respectively, not `core/config.py`'s `Settings`, so per the task's explicit
  scope (documenting `core/config.py`'s `Settings` class) they are left out of this table rather than
  scope-crept in.
- **Architecture**: the dead `backend/src/resumetailor/yaml_utils.py` reference replaced with
  `resume_schema/` (moved and split during wave 1); diagram extended to name
  `/api/health`, `/api/health/ready`, `/api/metrics`, and the background orphan reaper, all of which
  postdate the original diagram.
- Em-dash check run against the full rewritten file per `AGENTS.md` §9; one instance found in a table
  cell (`| — |` as a placeholder for "no default") and replaced with `none`.
